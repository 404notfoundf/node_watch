待核实的发行说明主张

  1. 发行说明存在明确的 “⚠️ Breaking Changes” 章节，声明 common_sqlite: “owner-only database files, WAL set in create_pool, per-database profiles” 与 wallet: “remove private-key UTXO export, which leaked the spend key”。上游已明确将其列为重大变更，但本次差异（仅版本号改动）不含 #8107、#8102 的实现，具体升级影响、数据库文件权限变化及导出功能移除的代码后果待核实。
  2. 发行说明称 “fix(validation): require the canonical script on side-chain claimable burns” 与 “fix(sidechain): weigh quorum certificates by signer voting power”，属共识变更声明（发行说明未声明硬分叉，也未给出激活高度），本次差异无对应验证代码，规则影响待核实。
  3. 发行说明称 “bound memory held for stalled yamux peers, RPC/sync streams and gRPC GetBlocks” 及 “bound messaging queues, fair inbound delivery, yamux window cap” 等内存/队列限制改动，本次差异无对应代码，实际内存影响待核实。
  4. 发行说明称安全修复 “remove private-key UTXO export, which leaked the spend key” 与 “prevent secret key leakage from malformed identity errors”，本次差异无对应代码，修复范围与受影响版本待核实。

AI 审查

代码已确认的发现

  1. 钱包数据库单向迁移（兼容性/运维）：base_layer/wallet/src/storage/sqlite_db/wallet.rs 将 CURRENT_SECONDARY_KEY_VERSION 升至 3 并把 wallet type 改为加密存储，Argon2Parameters::from_version 只接受 ≤2 与 3，测试 rolling_the_secondary_key_version_back_fails_to_open 明确回滚后无法打开。迁移后 v6.2.0 无法再读取该钱包库，升级前必须保留可回退副本。

  2. 旧钱包库副本明文私钥泄露警示（安全）：同文件 encrypt_plaintext_wallet_type 迁移时警告 provided-keys/ledger 类型 wallet type 含私有 view key（可能含 spend/comms 私钥）此前以明文 JSON 存于库文件，原文称 "Earlier copies or backups of this wallet database file contain them and should be treated as disclosed"。持有旧副本/备份的用户需按已泄露处理并轮换密钥或转移资金。

  3. 节点与 peer_sync 启动阻断（破坏性变更）：load_from_json 强制 0600，minotari_node/src/bootstrap.rs 与 minotari_peer_sync/src/main.rs 改用 load_tor_identity，身份文件权限非 0600 时以 ConfigError 退出（此前 bootstrap 路径不检查）。必须 chmod 600 或重建文件（重建会更换 onion 地址）。

  4. 钱包 gRPC 与 FFI 语义变化（兼容性/API）：applications/minotari_console_wallet/src/grpc/wallet_grpc_server.rs 新增 lookup_error，查询失败由 NOT_FOUND 改为 INTERNAL/DATA_LOSS，get_payment_by_reference 的历史 PayRef 查询失败不再返回空列表而是报错。FFI 的 wallet_get_pending_{inbound,outbound}_transaction_by_id 中 max_search_limit 被完全忽略，依赖旧语义的客户端行为会改变。

  5. 金额解析变严格（兼容性）：base_layer/transaction_components/src/tari_amount.rs 的 parse_amount 拒绝千位分隔符等旧可接受写法，配置或命令行沿用旧写法会导致解析失败、操作报错。

  6. min_peer_version 配置静默失效（兼容性）：comms/core/src/peer_validator/config.rs 将 min_peer_version 改为接受并忽略（warn_min_peer_version_ignored 仅告警），common/config/presets/c_base_node_c.toml、d_console_wallet.toml 删除该项，依赖该设置过滤低版本节点的运维会静默失去过滤能力。

  7. 超大 limit 的 OOM 路径修复（内存）：wallet_grpc_server.rs 的 GetAllCompletedTransactions 移除按客户端 limit 进行的 Vec::with_capacity(total_requested) 巨额预分配，消除该分配放大/OOM 路径。

  8. DHT 抗滥用与重放防护权衡（安全/稳定性）：comms/dht/src/inbound/decryption.rs 对无效签名/语义错误消息不再封禁来源而只丢弃（attribution rule 注释 "never bans"），comms/dht/src/dedup/dedup_cache.rs 在超过 10× 容量上限时驱逐未过期条目，comms/dht/src/config.rs 注明 "a message evicted that way can be accepted again"，洪泛压力下重放防护可能失效。

  9. 交易列表静默跳过坏行（稳定性/数据）：base_layer/wallet/src/transaction_service/storage/sqlite_db 的 decode_rows/DecodedRows 只记 error 日志并跳过无法解码行，存在坏行时列表返回不完整结果，单条查询改报 UndecodableRows。base_layer/wallet/src/wallet.rs 的 read_or_create_wallet_type 在 wallet type 行缺失且不允许初始化时直接报错，要求删除数据库或从助记词恢复。

  10. CipherSeed 序列化格式变化（兼容性/互操作）：base_layer/common_types/src/seeds/cipher_seed.rs 新写出加密种子（人类可读形式为 hex），反序列化兼容旧明文结构，但新写出的 JSON 形式旧版本无法读取，影响 seed 导出/导入的跨版本互操作。

待核实的发行说明主张

  1. 发行说明称 "chore(sidechain): use the published tari_sidechain 7.0.0 and tari_jellyfish crates"。代码确认 infrastructure/jellyfish/（tari_jellyfish）被删除、scripts/publish_crates.sh 移除相关发布条目，被删 lib.rs 文档称其哈希方案用于 sidechain 区块头 command_merkle_root 并须与 tari_sidechain 映射同一 scheme。已发布 crate 是否改变 sidechain 校验规则或共识行为未能核实，发行说明未声明硬分叉。

  2. 发行说明称 "fix(comms): check resolved dial addresses, per-address dialer failures" 与 "fix(comms-dht): relay received bytes verbatim, require canonical encodin"。分段审查未报告对应实现证据，拨号地址校验与 canonical encoding 要求对 P2P 连接及消息接受/转发行为的具体影响未能核实。

  3. 发行说明称 "fix(offline-signing): make multisig deposit and withdraw outputs recoverable by the recipient"。分段审查未报告对应实现证据，多签离线签名存取款输出的可恢复性改动未能核实。
