AI 审查

代码已确认的发现

  1. 破坏性变更（已确认）：base_layer/core/src_chain_storage/active_validator_node.rs（即 base_layer/core/src/chain_storage/active_validator_node.rs）为 ValidatorNodeEntry 新增 original_registration，deserialize_original_registration 刻意让旧版本写入的条目解码失败并提示“the chain database must be resynced”，该条目经 validator_node_store.rs 的 lmdb_get::<_, ValidatorNodeEntry> 进入 VN 集合与 validator_node_mr 计算。含验证节点注册记录的既有链库升级后必须全量重同步，否则 VN 查询与出块路径报解码错误。

  2. 硬分叉/共识（已确认）：base_layer/core/src/validation/aggregate_body/aggregate_body_chain_validator.rs 的 find_unknown_inputs 现在把 ContainsSTxO 与 UnknownInput 同等给予“body 内重建同 hash 输出”豁免，保留花费历史的归档节点对花费重建输出的 body 由 ContainsSTxO 拒绝变为接受，可提交区块集合发生变化。发行说明未声明硬分叉，代码注释表明该改动旨在消除归档与剪枝节点的判定分歧。

  3. 稳定性/数据（修复）：chain_storage/utxo_mined_info.rs 新增 MinedInfo::latest，base_node/comms_interface/inbound_handlers.rs、rpc/service.rs、query_service.rs 改为只有最新实例自身的花费才算已花费，CheckOutputSpentStatus、query_deleted、get_utxos_deleted_info 在重复输出场景下的结果随之改变。另 libtor 升级到 tari-libtor-core 49.15.2（内含 Tor 0.4.9.15，#8194），对应修复当前 Tor 共识下基节点直接退出的问题。

  4. 安全（修复）：applications/minotari_app_grpc/src/authentication/basic_auth.rs 与 server_interceptor.rs 以常数时间 Basic 认证和按 IP 退避（60 秒内 5 次失败后 50ms→60s、跟踪上限 1024 个 IP）替换每请求 Argon2id，降低暴露 gRPC 端点的 CPU 消耗攻击面。conversions/unblinded_output.rs 以 ZeroizeOutputKeys 在含错误返回的所有退出路径清零私钥，并为 5 个含私钥的 proto 消息脱敏 Debug。

AI 审查

代码已确认的发现

  1. 【安全】#8294 在 base_layer/mmr/src/merkle_proof.rs::verify 新增拒绝非叶子位置与 pos >= mmr_size，并在 merkle_mountain_range.rs 修正 find_leaf_index 与 get_leaf_hashes 的叶子查找和上界，可阻断以父节点哈希或越界位置通过的伪造 Merkle 证明。
  2. 【安全】#8323 在 base_layer/core/src/mempool/unconfirmed_pool.rs::remove_by_commitments_and_kernel_excesses 停止按 kernel 的 burn_commitment 匹配池内输出，防止他人伪造 burn_commitment 把未确认交易从内存池剔除。
  3. 【安全】#8266 与 #8322 在 comms/dht/src/network_discovery/admission.rs、join_gate.rs、on_connect.rs 为 Join gossip 与 OnConnect 对等同步加入每源预算、冷却和超时，并在 connectivity/metrics.rs 按转发因子重算 flood-ban 计数，缓解对等发现泛洪与误封禁。
  4. 【安全】#8169 在 applications/minotari_app_grpc/src/authentication/basic_auth.rs 截断日志中的 scheme 并拒绝含 : 的用户名，server_interceptor.rs 对非法凭据转为 fail-closed 拒绝全部请求，covenant 解析改用 borsh::from_slice 拒绝尾随字节。
  5. 【安全】minotari_app_utilities/src/identity_management.rs（对应 #8149）在身份文件公钥/NodeId 与私钥不一致时以 ExitCode::ConfigError 拒绝启动且不覆盖私钥，阻断私钥被替换后继续运行。
  6. 【稳定性/数据】#8245 在 base_layer/core/src/chain_storage/blockchain_database.rs 与 lmdb_db.rs 区分存储访问失败与数据损坏并在写锁下重验，健康或被并发改动的数据库不再被误判为损坏并触发回退。
  7. 【稳定性/数据】#8260 在 lmdb_db.rs::reset_chain_to_genesis 把越过剪枝视界的 rewind 改为单事务原子重置到创世（LostHeaderTip 保证重置须强于被删除的最强头，失败不改库），但剪枝节点一旦触发将被清空至高度 0 并需全量重同步。
  8. 【稳定性/数据】#8246 在 lmdb_db.rs 启动时修复或丢弃失效孤儿链尖并按子树驱逐孤儿，在 inbound_handlers.rs 对未知祖先或过旧 RandomX key 的块按每 peer 预算有界丢弃且不封禁。
  9. 【稳定性/数据】#8244 在 mempool/unconfirmed_pool.rs 等把未成熟或锁仓花费排除出区块模板，并在模板高度重检脚本与契约，失败者连同后代直接从池中移除，日后恢复有效的花费也需重新广播。
  10. 【稳定性/数据】horizon_state_sync/synchronizer.rs 改为最终 tranche 先提交再验 output root，失败时原子重置输出状态并检测 LocalOutputStateInconsistent，同时加入对端等待预算与 SlowPeerFailure 限速。
  11. 【稳定性/数据】validation/difficulty_calculator.rs 与 header_full_validator.rs 在无给定 target 时按链上下文 VM key 校验孤儿与侧链头 PoW，修复此前用主链 VM key 导致的分叉头误拒或误收。
  12. 【稳定性/数据】#8318 在 inbound_handlers.rs 用 MinDifficultyCache 把每算法目标回溯限制在 difficulty_block_window × 算法数，未命中算法改取 min_pow_difficulty，该 gossip 预校验门限在此场景变松但不改变最终区块规则。

待核实的发行说明主张

  1. 【硬分叉/共识】发行说明主张 fix(validation): check chain-linked timelocks at the height the body is mined at 与 fix(validation): tighten kernel burn commitment checks。代码已证实 aggregate_body_chain_validator.rs 的 verify_timelocks 由 current_height + 1 改为 current_height、aggregate_body_internal_validator.rs 的 check_total_burned 新增拒绝非 burn kernel 携带 burn_commitment，但材料未给出其他完整验证阶段的对照，无法确认最终有效区块/交易集合是否改变，发行说明未声明硬分叉。
