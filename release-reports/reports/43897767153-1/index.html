AI 审查

代码已确认的发现

  1. 共识验证规则变更（#8193）：blockchain_database.rs 的 inputs_and_outputs_match_header 现要求 inputs/outputs/kernels 排序且唯一，移动 coinbase 或反转顺序的 block 不再被视为 header 承诺的 body 且提供方被 ban（tests/node_comms_interface.rs、tests/block_sync.rs 覆盖）。发行说明未声明硬分叉、激活高度或分叉时间点。

  2. 验证裁决变化（#8191）：aggregate_body_chain_validator.rs 的 find_unknown_inputs 改为接受花费本 body 内重建输出的输入，裁决不再依赖节点保留的已花费历史，配套 validation/error.rs 新增 ValidationError::SpentInputs（不产生 ban 理由）及 validation/helpers.rs 的 check_input_is_utxo 改用 contains_output_hash，内存池接受花费再创建输出的交易而区块层双花仍被拒。

  3. 破坏性变更/数据迁移：ValidatorNodeEntry 新增必填字段 original_registration（lmdb_db.rs 写入），旧条目反序列化直接失败并提示 “the chain database must be resynced”。从 v6.3.0-pre.1 升级且链库含验证节点条目的节点必须重新同步链库，既有同步状态无法保留。

  4. 同步链选择与对端惩罚（#8160）：base_layer/core/src/base_node/sync/header_sync/synchronizer.rs 对短批次新增 claimed difficulty 校验，超报累计难度返回 PeerSentInaccurateChainMetadata 并惩罚对端，同时取消短批次前的提前换链，防止经短批次诱导切换到超报难度的分叉。

  5. mempool 中继与封禁策略（#8173、#8187）：mempool/service/inbound_handlers.rs 直接丢弃加密交易 gossip，明文消息来源一律 ban_peer；mempool/mempool_storage.rs 仅对 height_dependent: true 的输入脚本失败免禁，内核签名、range proof 等失败施加长封禁，混合网络中对端被封禁会更激进。

  6. gRPC 安全修复（#8170、#8166）：basic_auth.rs 以常量时间比较取代每请求 Argon2id 并新增每 IP 失败退避（5 次失败触发、指数退避封顶 60 秒、上限 1024 IP、回环豁免），口令改为 Zeroizing<Vec<u8>> 明文驻留内存（已披露的权衡）。conversions/unblinded_output.rs 在所有退出路径清零 spending_key/script_private_key 并脱敏 Debug。

  7. 数据完整性修复：horizon_state_sync/synchronizer.rs、db_transaction.rs 的 HorizonStateTreeUpdate.replaces_value 与 lmdb_db.rs 剪枝逻辑处理同一 tranche 内“花费+重挖相同输出”的状态树覆盖与实例删除，避免剪枝误删重挖实例。

  8. 依赖审计明示风险（#8186）：deny.toml 忽略 RUSTSEC-2026-0387（crypto-bigint 0.5 恒定时间路径含秘密相关分支），说明其仅经 pgp 用于 auto-update 哈希文件的公钥验签且无秘密标量运算，属上游明示接受的遗留风险。

  9. 首次配置默认值变更（#8123）：common/src/configuration/bootstrap.rs 与 configuration/utils.rs 中首次生成配置的 “mine (y/N)” 空行/非交互默认由“是”改为“否”，新装节点默认不再启用挖矿及随之暴露的 gRPC 方法集合；同条目所述的非 TTY CPU 自旋修复本身在已提供证据中未见对应实现。

待核实的发行说明主张

  1. #8194：发行说明称 “bundle Tor 0.4.9.15 so the base node no longer exits on the current Tor consensus”（修复当前 Tor 共识下基础节点直接退出），已提供的审查证据未报告对应实现，代码影响未核实。
  2. #8174：发行说明称 “keep walking an orphan's ancestry above the main tip”，孤儿块祖先遍历修复的代码影响未核实。
  3. #8175：发行说明称 “output index consistency”，输出索引一致性修复的代码影响未核实。
  4. #8030：发行说明称 “back up corrupt identity files before regenerating”，损坏身份文件备份行为的代码影响未核实。
  5. #8192：发行说明称 “handle stratum responses without a method field”，矿工 stratum 响应解析修复的代码影响未核实。

本版本为预发布版（v6.3.0-pre.2），不建议直接部署到生产环境；若从 v6.3.0-pre.1 升级，请先评估链库强制重新同步的成本（见第 3 项）。

AI 审查

代码已确认的发现

  1. 共识规则收紧：header_full_validator.rs 新增 check_kernel_mmr_size，kernel_mmr_size <= prev_header.kernel_mmr_size 的头被拒（KernelMmrSizeNotIncreasing，长封禁）。发行说明未声明硬分叉，但不同版本节点对相同头的接受判定可能分歧，属共识变更。
  2. 共识/时间锁语义变更：aggregate_body_chain_validator.rs 的 verify_timelocks 由 min_spendable_height > current_height+1 改为 > current_height，按区块出块高度校验，原先可进入该区块的临界时间锁交易现在被拒。
  3. 共识校验收紧：check_total_burned（链链接与内部校验器）及 transaction_builder 新增拒绝非 burn kernel 携带 burn_commitment 的规则，带该字段的旧式交易/区块被拒。
  4. 共识相关难度校验修正：validation/difficulty_calculator.rs 改用 chain_context.vm_key() 对副链/孤儿头按其自身链的 RandomX VM key 校验难度，删除原 “KNOWN OPEN ISSUE” 行为，副链头的难度接受判定随之改变。
  5. 破坏性变更（gRPC 认证）：basic_auth.rs::BasicAuthCredentials::new 拒绝用户名含 :，server_interceptor.rs 对该配置进入 reject_all，升级后含此用户名的既有配置下全部 gRPC 请求（含挖矿接口）返回 Unauthenticated，需改配置；generate_header 亦拒绝非 UTF-8 密码，grpc_authentication.rs 密码序列化改写为 <redacted> 且反序列化拒绝该占位符，配置序列化-回读流程会失败。
  6. 数据/运维（#8260、#8263）：lmdb_db.rs 的 reset_chain_to_genesis/MetadataKey::LostHeaderTip 使剪枝节点越过剪枝高度的回退变为单次写入的整链重置到创世，孤儿清空、节点需从头重新同步（失败的重置不动库）。
  7. 安全修复：base_layer/mmr/src/merkle_proof.rs 的 MerkleProof::verify 新增拒绝非叶位置与 pos >= mmr_size，find_leaf_index 改为逐叶比较，修复叶哈希与父节点哈希碰撞时的查找错误，伪造/越界证明现被拒。
  8. 安全/内存风险：.cargo/audit.toml 新增豁免 RUSTSEC-2026-0459（bundled SQLite < 3.54.0 配合构造的 -wal 文件可返回未初始化页缓存内存），理由是 diesel 限制 libsqlite3-sys < 0.39，属有意接受的风险，minotari_utils dbstats 打开不可信 DB 时可触发。
  9. 稳定性修复：blockchain_database.rs 的 verify_blockchain_consistency_for_height/rewind_if_still_corrupt 与 ChainStorageError::is_storage_access_failure 区分存储访问失败和真实损坏，避免健康库被误报损坏并触发回滚。
  10. 矿工影响（#8244）：mempool.rs::retrieve 增加 height/prev_hash 参数，unconfirmed_pool.rs 的 TemplateFilter 复检后把高度过期交易连同后代移出池，出块模板内容与池内交易存留随之改变。
  11. 兼容性（#8265）：peer mempool RPC 的 get_state（method id 2）被移除，调用方收到 UnsupportedMethod，方法号保留不再复用（发行说明称该方法未被使用）。
  12. 兼容性（#8322）：comms/dht/src/rpc/service.rs 的 get_peers 固定 features = Some(COMMUNICATION_NODE)，include_clients 自 v6.3.0 起被忽略、客户端节点不再返回，依赖该 RPC 枚举客户端的工具失效。
  13. 兼容性/启动（#8225、#8322）：comms/dht/src/config.rs 对 flood_ban_max_msg_count、flood_ban_timespan 新增范围硬校验，越界配置使节点启动加载失败，common/src/configuration/name_server.rs 把 system/<后缀> 由可解析改为报错。
  14. 稳定性/传播（#8322、#8266）：outbound/broadcast.rs 新增 ForwardBudget 按来源与目标限额截断转发，超额消息直接丢弃，connectivity/metrics.rs 重写洪水计数（转发流量按 10 倍限额计），高负载下交易/区块转发会被削减，代码注释自述诚实中继仍可能被邻居封禁。

待核实的发行说明主张

  1. #8257 “derive the pruning target from validated headers”：当前差异未见剪枝目标计算实现，代码影响待核实。
  2. #8258 “only disable block acceptance after a peer has proven a stronger chain”：未见块接受禁用逻辑的实现差异，影响待核实。
  3. #8204 “do not record out-of-sequence headers as bad blocks” 与 #8329 “refresh cached chain metadata after a rewind”：header-sync 相关实现未在各段匹配到证据，错误 bad block 记录与元数据刷新的影响待核实。
  4. #8201 “horizon sync resume and peer handling improvements”：仅见 horizon_state_sync/synchronizer.rs 的 MMR 位置校验，断点续传与 peer 处理的实现未匹配到证据。
