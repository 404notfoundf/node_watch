AI 审查

  1. 共识规则变化（未声明硬分叉）：base_layer/core/src/validation/aggregate_body/aggregate_body_chain_validator.rs 的 find_unknown_inputs 现在在同一体重新创建被花费输出时跳过 ContainsSTxO，此类区块在 pre.2 有效但在 pre.1 被拒，混跑期间新旧节点会对同一区块给出不同结论。发行说明将其描述为“consistent verdicts for re-created outputs”，代码证据已确认，但发行说明未声明硬分叉。

  2. 验证收紧：chain_storage/blockchain_database.rs 的 inputs_and_outputs_match_header 现在要求 inputs/outputs/kernels 均 is_all_unique_and_sorted 才认定 body 为 header 承诺的那个体；tests/helpers/block_builders.rs 注释与 tests/tests/node_comms_interface.rs 显示仅移动 coinbase 位置且 MMR 根仍匹配的 body 会被拒收并对端点 ban，改变区块接受与 ban 归因行为。

  3. 破坏性存储格式变更（发行说明未提及）：chain_storage/active_validator_node.rs 的 ValidatorNodeEntry 新增必需字段 original_registration，反序列化对旧记录直接报错并要求“the chain database must be resynced”，已含 VN 条目的 LMDB 节点升级后必须重新同步数据库。

  4. gRPC 认证改造带来残余安全风险：basic_auth.rs / server_interceptor.rs 用常量时间比较替代每请求 Argon2id 并改为明文驻留内存，暴力尝试成本改由按 IP 退避限制，但回环地址、remote_addr 为 None 的传输不计数且 MAX_TRACKED_PEERS = 1024 驱逐配合轮换 IP 可重置 5 次预算，同时共享 NAT 后的被封 IP 会连带锁死合法客户端。

  5. 矿工收益风险：applications/minotari_miner/src/stratum/stratum_controller/controller.rs 将客户端通道改为 sync_channel(16)，try_send_to_client 在队列满时直接丢弃 FoundSolution（仅计入 shares_dropped 日志），旧版无界 send() 不会丢弃已找到的份额。

  6. 矿工崩溃修复：applications/minotari_miner/src/stratum/controller.rs 的 classify_message 旧代码对无 method 字段的响应执行 expect("Already checked") 可能 panic，现已按响应/通知分类处理。

  7. Mempool 封禁策略变化：mempool/mempool_storage.rs 的 is_tip_dependent 与 aggregate_body_internal_validator.rs 新增的 AggregatedBodyValidationError::InputScript { height_dependent } 使仅高度相关的输入脚本失败豁免封禁，其余脚本失败的对端转为长期封禁（两段代码证据互相印证）。

  8. 供应链残余风险：deny.toml 明确忽略 RUSTSEC-2026-0387（crypto-bigint 0.5 常量时间操作的时序问题），忽略理由声明的适用范围（仅 pgp 公钥验签等）在现有材料中无法核实，未来若存在密钥标量用法将被该忽略覆盖。

（预发布版本，上述共识与存储格式变化在生产部署前需要额外评估。）

  • 重点标记： 🚨 破坏性变更（已确认） · 🚨 重大共识变更（已确认） · 🚨 兼容性（已确认） · 🚨 安全（风险） · 🚨 稳定性/数据（风险）

AI 审查

  1. 共识变更（已确认）：aggregate_body_chain_validator.rs::verify_timelocks 的边界收紧一格并改传 spend_height，原本恰好在 header.height+1 可花费的 kernel lock/maturity 交易在区块 H 由接受变为拒绝。这是共识规则变更，发行说明未声明硬分叉，未协调升级会使新旧节点在该边界上共识不一致。

  2. 共识变更（已确认）：check_total_burned 新增拒绝带 burn_commitment 但 KernelFeatures 非 burn 的 kernel，validation/header/header_full_validator.rs::check_kernel_mmr_size 新增 KernelMmrSizeNotIncreasing 拒绝并触发长 ban，两者都会使旧规则下已接受的历史区块/区块头失效。发行说明未声明硬分叉。

  3. 破坏性变更/兼容性（已确认）：mempool/rpc/mod.rs 移除 get_state，仍在调用 method 2 的旧节点对升级节点会收到 UnsupportedMethod。wallet_ffi/src/lib.rs::scrape_wallet 现在仅返回首个 TxId、无未花费输出时返回 0 且可能生成多笔交易，按旧契约处理返回值的 FFI 调用方会误判失败或漏掉交易。

  4. 兼容性（已确认）：basic_auth.rs/server_interceptor.rs 将用户名含 : 的既有 gRPC 配置改为启动报错并拒绝所有请求（reject_all），此类部署升级后 gRPC 全面不可用。另 common_types/src/grpc_authentication.rs 序列化写入 <redacted> 而反序列化拒绝该字面量，序列化后回读的配置会丢失口令并解析失败；ServerAuthenticationInterceptor::new 对超长用户名/非 UTF-8 口令返回 None 时调用方如何处理未在材料中显示，是否失效开放需人工复核。

  5. 安全（风险）：comms/dht/src/dedup/mod.rs 将非首个投递者的重复消息记为 uncounted，inbound/metrics.rs::claimed_flood_series 又把签名解码失败的报文归入阈值高 10 倍的 Forwarded 系列，重放洪泛和垃圾签名的过期报文可绕过 per-peer flood-ban 限额。comms/dht 示例配置的 ban_duration = 120、ban_duration_short = 60 与 config.rs 默认 2 小时/10 分钟不符，采用示例配置会显著缩短封禁。

  6. 稳定性/可用性（风险）：horizon_state_sync/error.rs 将 FinalOutputRootMismatch 与 OutputAlreadyStored 设为不 ban 且可归因于恢复状态，synchronizer.rs 对同一节点清空检查点后从高度 1 重建全部 output 状态，恶意 peer 可反复触发全量重建。peer_wait_budget 在 initial_max_sync_latency 为 0 时预算经 checked_div(...).unwrap_or(u128::MAX) 变为无限，慢速保护失效。

  7. 稳定性/数据（已确认）：chain_storage 的 rewind_or_reset_to_height + reset_chain_to_genesis 将越过剪枝地平线的回退改为原子清空链表并重种创世块，此类回退后节点状态等同从头同步，运维需预期全量重同步。

  8. 稳定性（证据不完整）：state_machine_service/state_machine.rs 与 header_sync/synchronizer.rs 中 set_disable_add_block_flag 的设置/清除路径较多，材料未能确认 PendingChainRewind::Reset 及 rewind_blockchain(...)? 错误路径是否必然清除该标志，若存在遗漏路径将长期禁用区块受理，建议人工复核全部状态转移出口。
